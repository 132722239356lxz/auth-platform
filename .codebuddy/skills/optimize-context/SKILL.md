# 上下文汇总优化（降低 token 消耗）

你是"上下文压缩器"：**只读**地梳理当前任务上下文，产出一份紧凑、可复用的摘要，帮后续会话/续聊少花 token。不修改任何代码。

## 第一步：采集当前状态信号

用内联命令抓取真实状态（不要凭记忆）：

```
!`git status --short`
!`git diff --stat 2>/dev/null | tail -20`
!`git log --oneline -10 2>/dev/null`
!`git diff --staged --stat 2>/dev/null | tail -20`
```

必要时 `Read`/`Grep` 关键文件，确认改动意图与未提交的实质内容。

## 第二步：提炼（保留什么 / 丢弃什么）

**保留**（后续继续工作真正需要）：
- 任务目标与当前进度
- 已做的改动 + 改动**原因**（文件:行号 + 一句话意图）
- 关键决策与分歧点
- 待办 / 阻塞项
- 项目约束（本仓库：统一返回 `ApiResponse<T>` 或 `R<T>`、Nacos `@nacos.*@` 占位符、common-core 复用、不硬编码凭据）
- 已知坑（如 Spring Authorization Server API 误用、端口冲突）

**丢弃**：
- 冗长日志、重复试错过程、无关文件全量内容
- 已回滚/放弃的路径
- 可从代码直接读出的细节（只留指针，不贴全文）

## 第三步：产出紧凑摘要

输出结构化 Markdown，**控制在 ~60 行内**：

```
## 上下文摘要
### 目标
<一句话当前任务>

### 已完成改动
- `<文件>` — <意图/原因>
- ...

### 关键决策
- <决策 + 理由>

### 待办 / 阻塞
- [ ] <事项>

### 约束与已知坑
- <本仓库约定 / 易错点>

### 如何复用这份摘要（省 token）
- 作为新会话开场上下文，或写入 CODEBUDDY.md / 提交说明；
- 大范围代码探索交给子代理（独立上下文窗口），主会话只收摘要，避免上下文被无关内容塞满。
```

## 约束

- **只读**，不改代码、不提交。
- 真实反映当前 git/代码状态，禁止编造改动或进度。
- 面向"继续工作所需的最小信息"，宁缺毋滥。
