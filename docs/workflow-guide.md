# 审批流操作指南

> **适用版本**: V2.0+  
> **文档用途**: 指导管理员配置审批流程、用户发起和审批申请

---

## 一、系统概述

审批流模块实现了灵活的流程定义和审批流转功能，支持：

- **串行审批**：多个审批人按顺序逐个审批
- **并行审批**：同一级别的多个审批人同时审批（会签模式）
- **条件分支**：根据申请内容动态选择审批路径
- **驳回与转交**：支持驳回到上一节点/发起人，以及转交他人审批

**涉及角色**：

| 角色 | 职责 |
|------|------|
| 系统管理员 | 创建和管理审批流程定义 |
| 审批人 | 处理待审批的申请（通过/驳回/转交） |
| 普通用户 | 发起审批申请 |

## 二、前置准备

### 2.1 数据库初始化

执行审批流表结构创建脚本：

```bash
mysql -u root -p your_database < auth-flow/src/main/resources/db/schema-workflow.sql
```

### 2.2 导入测试数据（可选）

```bash
mysql -u root -p your_database < data/seed-workflow.sql
```

### 2.3 添加菜单权限

在系统管理→菜单管理中添加以下菜单（或执行 seed SQL）：

| 菜单名称 | 权限标识 | 类型 |
|----------|----------|------|
| 流程定义 | workflow:definition:list | 菜单 |
| 流程定义-新增 | workflow:definition:add | 按钮 |
| 流程定义-编辑 | workflow:definition:edit | 按钮 |
| 流程定义-删除 | workflow:definition:delete | 按钮 |

然后将这些权限授予管理员角色。

### 2.4 启动服务

确保 auth-flow 服务（端口9001）已注册到 Nacos 并正常运行。

## 三、创建审批流程定义

### 3.1 进入流程定义页面

登录管理后台 → 点击左侧「工作流审批」→「流程定义」

### 3.2 新建流程定义

1. 点击「新建流程」按钮
2. 填写基本信息：
   - **流程 Key**：唯一标识，如 `PERMISSION_APPROVAL`（英文、下划线）
   - **流程名称**：如「权限申请审批」
   - **分类**：选择 PERMISSION（权限）/ RESOURCE（资源）/ ROLE（角色）
   - **描述**：可选，简要说明该流程用途
3. 点击确定

### 3.3 配置审批节点

流程创建后，在右侧节点设计区添加审批步骤：

1. **点击「添加节点」**，新增一个审批步骤
2. **配置节点参数**：

   | 参数 | 说明 | 示例 |
   |------|------|------|
   | 节点名称 | 审批步骤名称 | 「部门经理审批」 |
   | 节点类型 | APPROVAL（审批）/ CONDITION（条件）/ START / END | APPROVAL |
   | 审批人策略 | SPECIFIC=指定人 / ROLE_BASED=角色 / DEPARTMENT_LEADER=部门领导 | SPECIFIC |
   | 审批人 | 审批人用户名，多个用逗号分隔 | lisi,wangwu |
   | 会签模式 | 开启后需所有审批人都通过才流转 | 关闭 |
   | 驳回策略 | TO_PREV=回退上一节点 / TO_START=退回发起人 | TO_START |
   | 排序号 | 越小越先执行 | 0 |
   | 超时时间 | 审批超时时间（小时），0=不限时 | 24 |

3. **调整顺序**：通过排序号控制审批先后顺序（0→1→2）
4. **点击「保存节点」**，更新节点配置

### 3.4 典型配置示例

**示例1：简单单级审批（申请人→经理）**

| 节点名称 | 类型 | 审批人 | 顺序 |
|----------|------|--------|------|
| 经理审批 | APPROVAL | lisi | 0 |

**示例2：两级审批（申请人→经理→总监）**

| 节点名称 | 类型 | 审批人 | 顺序 |
|----------|------|--------|------|
| 部门经理审批 | APPROVAL | lisi | 0 |
| 总监审批 | APPROVAL | wangwu | 1 |

**示例3：会签审批（需 lisi 和 wangwu 都通过）**

| 节点名称 | 类型 | 审批人 | 会签 | 顺序 |
|----------|------|--------|------|------|
| 联合审批 | APPROVAL | lisi,wangwu | ✅ | 0 |

### 3.5 启用流程

流程创建后默认状态为「启用」。如需要暂停该流程，可在列表点击状态开关切换为「停用」。停用状态的流程不会出现在发起申请的可选列表中。

## 四、发起审批申请

### 4.1 用户操作步骤

1. 登录系统 → 点击「工作流审批」→「发起申请」
2. 选择要使用的审批流程（如「简单审批流程」）
3. 填写申请信息：
   - **申请标题**：如「申请系统管理员权限」
   - **申请内容**：详细描述申请原因和内容
4. 申请人自动填充为当前登录用户
5. 点击「提交申请」

### 4.2 审批流转过程

```
用户提交 → [节点1: 部门经理审批] → [节点2: 总监审批] → 通过 ✅
              ↓ 驳回                    ↓ 驳回
           退回发起人              退回上一节点
```

## 五、审批操作

### 5.1 审批人处理待审批

1. 登录系统 → 「工作流审批」→「审批列表」→「待我审批」标签
2. 点击要处理的申请「查看详情」
3. 在详情页底部执行审批操作：

| 操作 | 说明 | 后续流程 |
|------|------|----------|
| **通过** | 同意该申请 | 流转到下一审批节点或结束 |
| **驳回** | 拒绝该申请 | 根据驳回策略退回上一节点或发起人 |
| **转交** | 转给其他人审批 | 新审批人收到该任务，需填写目标用户名 |

4. 填写审批意见（可选但建议填写）

### 5.2 查看审批进度

在流程详情页，可以查看：
- **基本信息**：标题、状态、申请人、创建时间、当前节点
- **审批记录时间线**：每个节点的审批人、操作结果、审批意见和时间
- **当前状态**：审批中(PENDING)/已通过(APPROVED)/已驳回(REJECTED)/已撤回(WITHDRAWN)

### 5.3 撤销申请

申请人可以在「我的申请」中撤回状态为「审批中」的申请（需后端支持 WITHDRAW 操作）。

## 八、常见问题

### Q: 为什么我创建的流程在发起申请时看不到？

A: 请检查流程定义状态是否为「启用」。停用状态的流程不会出现在发起申请的列表中。

### Q: 审批人可以同时是申请人吗？

A: 可以。但建议避免此情况，如需自我审批建议使用更高级别的审批人。

### Q: 如何修改已创建的审批流程节点？

A: 在流程定义页面，点击左侧列表中的目标流程，右侧会显示当前节点配置。修改节点参数后点击底部的「保存节点」按钮即可更新。

### Q: 驳回后申请人可以重新提交吗？

A: 当前暂不支持直接重新提交。申请人需要重新发起一个新的申请。

### Q: 会签模式和串行审批有什么区别？

A: 串行模式下多个审批人按顺序逐个审批（前一个通过后到下一个）。会签模式下，节点上的所有审批人都需要审批通过才算该节点通过。例如会签节点配置了 lisi 和 wangwu，则两人都必须点通过才流转到下一节点。
